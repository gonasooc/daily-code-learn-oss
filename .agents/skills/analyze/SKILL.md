# $analyze 스킬

오늘(또는 지정된 날짜)의 리포트를 `prompts/analyze.md` 기준으로 분석하여 학습용 마크다운을 생성한다.

## 사용법

- `$analyze` — 오늘 날짜의 리포트 분석
- `$analyze 2026-03-12` — 특정 날짜의 리포트 분석

## 실행 절차

프로젝트 루트에서 실행한다. `config/profiles.json`의 `outputDir`을 **리포트 기준 경로**로 사용하며, 생략 시 `./reports`다. 상대 경로는 CLI와 같이 실행 디렉터리 기준으로 해석한다. 아래 `{reportDir}`은 이 경로를 뜻한다.

1. **날짜 결정**: 인자가 있으면 해당 날짜, 없으면 오늘 날짜(`YYYY-MM-DD` 형식)를 사용한다.
2. **리포트 읽기**: `{reportDir}/{날짜}/` 디렉토리에서 `analysis.md` 파일과 `-analysis.md`로 끝나는 파일을 제외한 생성 리포트 `.md` 파일을 읽는다.
   - 날짜 헤더와 `- 저장소:`의 전체 `root/저장소 상대경로`로 식별한다. Markdown 표기용 이스케이프와 코드 구분자는 이름에 포함하지 않는다. 중간 디렉터리를 버리거나 마지막 이름만으로 합치지 않는다.
   - 같은 날짜·전체 저장소 이름의 구형 리포트와 현재 리포트가 공존하면 `<!-- daily-code-learn-report:v1:... -->` 식별 마커가 있는 현재 리포트 하나를 우선한다. 구형 이름만으로 저장소를 확정할 수 없거나 현재 파일이 여러 개면 임의로 합치지 않고 모호한 후보를 알린다.
   - 디렉토리가 없거나 분석 대상 `.md` 파일이 없으면 "해당 날짜({날짜})에 리포트가 없습니다."라고 안내하고 종료한다.
3. **분석 기준 확인**: `prompts/analyze.md` 파일을 읽고, 그 출력 구조와 선별 기준을 따른다.
4. **분석 수행**: 모든 프로젝트/주요 변경은 `작업 커버리지` 표에 포함하고, 핵심 항목 1~3개만 `상세 학습`으로 분석한다.
5. **결과 저장**: 분석 결과를 `{reportDir}/{날짜}/codex-analysis.md`로 저장한다.
6. **텔레그램 전송**: `config/profiles.json`의 `telegram.enabled`가 `true`일 때만 아래 명령으로 전송한다. 꺼져 있거나 설정이 없으면 `설정에 따라 전송 생략`으로 완료하며 notifier를 호출하지 않는다.
   ```bash
   python3 lib/notifier.py "{reportDir}/{날짜}/codex-analysis.md" "{날짜}"
   ```
   - 전송 실패 메시지가 출력되면 완료로 넘기지 말고 실패 내용을 사용자에게 알려준다.
7. **완료 메시지**: 저장 경로, 분석한 리포트 목록, 텔레그램 전송 결과를 출력한다.
