아래는 오늘 작업한 Git 커밋 이력과 실제 코드 diff이다.
이 내용을 바탕으로 **학습용 분석 마크다운**을 작성해줘.

## 작성 원칙

- **독자**: 프론트엔드 4년차 개발자, 풀스택으로 확장 중. 4년차가 이미 아는 기초(변수 선언, JSX 문법, 기본 React hooks 사용법 등)는 생략한다.
- **목적**: 코드 리뷰 기록이 아니라 **퇴근길에 읽는 학습 자료**다. 읽고 나면 "오늘 뭘 배웠는지" 말할 수 있어야 한다.
- **읽기 환경**: 모바일 화면에서 읽는다. 문장은 짧게 쓰고, 코드 블록은 한 블록당 **10줄 이내**로 유지한다.
- **분량 목표**: 전체 결과는 대략 **180~250줄** 안에서 끝낸다. 대형 diff가 많아도 상세 분석 항목을 늘리지 말고 선별한다.
- **중복 제거**: 같은 패턴이 여러 커밋이나 프로젝트에 반복되면 대표 사례 1개만 상세 분석하고 나머지는 커버리지 표에서 요약한다.

## 출력 구조

문서는 **전체 커버리지 + 선별 상세** 구조로 작성한다.

---

### 1. 오늘의 학습 요약

- 핵심 학습 항목 1~3개를 **한 줄씩** 요약한다.
- 각 항목은 `**주제명**: 설명` 형식으로 쓴다.
- 상세 분석하지 않을 항목은 이 섹션에 섞지 않는다. 제외/참고 항목은 다음 `작업 커버리지` 표에서 다룬다.

예시:

```md
## 오늘의 학습 요약
- **커서 기반 페이지네이션**: 정렬 키 스냅샷을 커서로 삼아 무한 스크롤 목록의 중복·누락을 줄이는 패턴
- **한글 slug 정규화**: 저장·조회 경계에서 NFC를 맞춰 눈에는 같은 문자열이 검색되지 않는 문제를 막는 처리
```

---

### 2. 작업 커버리지

모든 프로젝트와 주요 커밋/변경 묶음을 표로 한 번씩 언급한다.
이 표는 "무엇을 읽었고, 무엇을 상세 분석하지 않았는지"를 보여주는 누락 방지 장치다.

필수 형식:

```md
## 작업 커버리지
| 프로젝트 | 커밋/변경 | 분류 | 상세 여부 | 이유 |
| --- | --- | --- | --- | --- |
| project-a | 커밋 2건: 기능 추가, API 정리 | 핵심 | 상세 | 새 API 설계 판단이 있음 |
| project-b | 이미지 교체, 문구 수정 | 참고 | 요약만 | 학습 포인트가 낮음 |
```

분류 기준:

- `핵심`: 상세 학습 후보. 새 패턴, 새 API, 아키텍처 판단, 재발 가능한 버그 원인이 있는 변경.
- `참고`: 읽었지만 상세 분석하지 않는 변경. 반복 스타일, 기존 패턴 복사, 설정값/문구/이미지 변경.
- `제외`: diff가 없거나 학습 가치가 거의 없는 변경. lockfile, 빌드 산출물, ownership 확인 파일, 단순 이동/삭제.

상세 여부:

- `상세`: 아래 `상세 학습`에서 다룬다.
- `요약만`: 표의 이유만 남기고 본문으로 끌고 가지 않는다.

---

### 3. 상세 학습

`작업 커버리지`에서 `상세`로 표시한 핵심 항목만 분석한다.
상세 학습 항목은 **1~3개**로 제한한다.

각 항목은 아래 형식을 따른다.

```md
## 상세 학습

### 1. 주제명

#### 변경 의도
- 무엇이 바뀌었는지와 왜 바뀌었는지를 함께 설명한다.
- 버그 수정, 기능 추가, 리팩토링, 설정 변경 중 무엇인지 구분한다.

#### 핵심 원리
- 사용된 패턴, 라이브러리 API, 설계 판단을 원리 중심으로 설명한다.
- 기초 문법 설명은 생략한다.

#### 실무 메모
- 기억할 점과 주의사항을 2~4개 불릿으로 압축한다.

#### 대안 검토
- 대안 비교가 실제 학습 가치가 있을 때만 작성한다.
- 대안이 명확하지 않거나 단순 취향 차이라면 이 섹션은 생략한다.
- 작성할 경우 코드 예시는 10줄 이내로 제한하고, 비교표도 2~4행 안에서 끝낸다.

#### 점검 질문
- 응용 여부를 확인할 질문 1개를 기본으로 쓴다.
- 정말 필요할 때만 2개까지 쓴다.
```

상세 학습 작성 규칙:

- 한 항목 안에서 설명을 반복하지 않는다.
- 코드 예시는 diff에서 핵심만 발췌하거나, 더 짧은 등가 예시로 바꿔도 된다.
- 원본 방식과 대안 비교가 중요하지 않으면 `대안 검토`를 생략한다.
- 단순 반응형 보정처럼 같은 패턴이 반복되는 작업은 대표 원리만 짚고 나머지는 커버리지 표에서 처리한다.

---

### 4. 오늘의 한 줄 정리

마지막에는 다시 볼 가치가 있는 내용만 1~3개로 압축한다.
상세 본문에 없는 새 내용을 추가하지 않는다.

예시:

```md
## 오늘의 한 줄 정리
- 커서는 정렬 키의 스냅샷이므로, 정렬이 복합이면 커서 조건도 복합이어야 한다.
- 외부 입력 문자열은 저장·조회 경계에서 같은 유니코드 정규화 형식으로 맞춘다.
```

## 출력 형식

- 마크다운으로 작성한다.
- 한국어로 작성한다.
- 프로젝트별 구분은 `작업 커버리지` 표에서 보장한다.
- 상세 학습은 프로젝트별 나열이 아니라 학습 주제별로 묶어도 된다.
- 분석에서 제외한 항목도 `작업 커버리지` 표에는 반드시 남긴다.
- 불필요하게 장황한 배경 설명은 줄이고, 판단 기준과 배울 점을 먼저 쓴다.
