# /publish 스킬

`/dig` 이후의 대화를 **"내가 몰랐던 것"** 중심으로 정리해 프로젝트별 디렉터리에 저장한다. 트랜스크립트가 아니다. 목적은 나중에 다시 열어 복기하는 것이므로, 6개월 뒤에 읽어도 무엇을 몰랐고 무엇을 알게 됐는지 바로 보여야 한다.

## 사용법

- `/publish` — 대화에서 가장 최근 `[dig 시작: …]` 마커의 프로젝트와 날짜를 쓴다
- `/publish muah-web` — 마커가 여러 개일 때 프로젝트를 명시한다

## 실행 절차

프로젝트 루트에서 실행한다. `config/profiles.json`의 `outputDir`을 `{reportDir}`로 사용하며, 생략 시 `./reports`다. 상대 경로는 CLI와 같이 실행 디렉터리 기준으로 해석한다.

### 1. 범위 확정

- 대화에서 가장 최근의 `[dig 시작: {slug} {날짜}]` 마커를 찾는다. 인자가 있으면 그 프로젝트의 가장 최근 마커.
- 프로젝트는 전체 `root/저장소 상대경로`, slug, 또는 마지막 이름으로 대조한다. 마지막 이름이 여러 저장소와 일치하면 후보를 알리고 전체 이름을 받아 확정한다. 전체 이름은 해당 dig의 리포트·대화에서 가져오며 slug의 `--`를 `/`로 바꿔 추측하지 않는다.
- 마커가 없으면 `먼저 /dig 를 실행하세요`를 안내하고 종료한다.
- 정리 대상은 **선택한 마커 이후부터 다음 `[dig 시작: …]` 마커가 있는 메시지 직전까지**다. 다음 마커가 없으면 현재까지다. 다음 dig의 첫 분석 메시지도 제외하여 다른 프로젝트의 질문·답변이 섞이지 않게 한다.

### 2. 내용 추출

마커 이후 대화에서 다음을 뽑는다.

- **맥락** — 어떤 커밋(SHA)과 변경을 놓고 이야기했는지 한 줄.
- **몰랐던 것** — 사용자가 물은 것, 또는 답을 듣고 새로 알게 된 것. 항목마다:
  - **Q** — 질문. 사용자 표현에 가깝게, 한 문장.
  - **A** — 답의 핵심 한 줄.
  - **→** — 새로 알게 된 것. "왜 몰랐는지"나 "어디서 헷갈렸는지"가 드러나면 복기 가치가 높다.
- **다음에 볼 것** — 대화 중 "나중에", "확인 필요", "다음에"로 미뤄진 것.

**질문이 하나도 없었으면**(첫 턴만 읽고 끝) 첫 턴 분석에서 새로웠을 만한 것을 골라 "몰랐던 것"을 채우지 **않는다.** `질문 없음`으로 남긴다. 억지로 만든 항목은 복기 가치가 없고, 진짜 몰랐던 것 사이에 섞이면 그것들의 신호를 흐린다.

### 3. 저장

- 경로: `{reportDir}/dig/{slug}/{날짜}.md`
- `{reportDir}/dig/{slug}/` 가 없으면 만든다.
- 기존 폴더의 기록은 첫 제목에 있는 전체 저장소 이름이 선택한 프로젝트와 같은지 확인한다. 다르면 slug 충돌을 알리고 다른 저장소의 기록에 추가하지 않는다.
- 파일이 **이미 있으면**(같은 날 두 번째 dig) 덮어쓰지 않고 맨 아래에 새 절을 추가한다. 절 제목의 시각으로 구분한다.

형식:

```md
# {root/repo} · {날짜}

## {HH:MM} · {SHA들}

**맥락**: {한 줄}

### 몰랐던 것
1. **Q** {질문}
   **A** {한 줄}
   → {알게 된 것}
2. …

### 다음에 볼 것
- …
```

파일이 새로 만들어지는 경우에만 첫 줄 `# {root/repo} · {날짜}`를 쓴다. 추가하는 경우 `## {HH:MM} · …` 절부터 붙인다.

### 4. 완료 메시지

저장 경로, 이번에 남긴 "몰랐던 것" 개수, 그리고 `{reportDir}/dig/{slug}/`에 쌓인 파일 수를 출력한다. 텔레그램 전송은 하지 않는다.
