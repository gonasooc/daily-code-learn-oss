# /dig 스킬

특정 프로젝트의 **그날 diff를 기준으로**, 필요하면 해당 저장소의 코드를 직접 읽으며 후속 질문을 이어가는 대화형 분석을 시작한다. 시작할 때 이 프로젝트에서 지난 dig에서 몰랐던 것을 먼저 꺼내 복기한다. 대화가 끝나면 `/publish`로 기록을 남긴다.

`/analyze`가 "그날 전체를 넓게"라면, `/dig`는 "한 프로젝트를 깊게, 그리고 시간축으로"다.

## 사용법

- `/dig` — 오늘 리포트가 있는 프로젝트 목록을 보여주고 끝낸다
- `/dig muah-web` — 오늘 날짜의 muah-web을 판다
- `/dig muah-web 2026-08-04` — 특정 날짜

프로젝트는 전체 `root/저장소 상대경로`(`vlending/team/muah-web`) 또는 마지막 조각(`muah-web`)으로 지정한다. 중첩 저장소는 중간 경로도 식별자에 포함한다.

## 실행 절차

프로젝트 루트에서 실행한다. `config/profiles.json`의 `outputDir`을 `{reportDir}`로 사용하며, 생략 시 `./reports`다. 상대 경로는 CLI와 같이 실행 디렉터리 기준으로 해석한다. 분석과 dig 기록도 이 경로 아래에서 찾는다.

### 1. 날짜와 프로젝트 확정

- **날짜**: 두 번째 인자가 있으면 그 날짜, 없으면 오늘(`YYYY-MM-DD`).
- `{reportDir}/{날짜}/`에서 `analysis.md`와 `-analysis.md`로 끝나는 파일을 **제외한** 생성 리포트를 나열한다. 날짜 헤더와 `- 저장소:`에서 전체 `root/저장소 상대경로`를 읽고 Markdown 이스케이프와 코드 구분자를 이름에서 제거한다.
- 같은 날짜·전체 저장소 이름의 구형 파일과 현재 파일이 공존하면 `<!-- daily-code-learn-report:v1:... -->` 마커가 있는 현재 파일 하나를 우선한다. 구형 이름만으로 저장소를 확정할 수 없거나 현재 파일이 여러 개면 후보를 알리고 임의로 선택하지 않는다.
- **프로젝트 인자가 없으면**: 그 목록을 출력하고 종료한다.
- **프로젝트 인자가 있으면**: 이름이 `root/repo` 전체 또는 마지막 조각과 일치하는 리포트를 고른다.
  - 일치가 없으면: `{reportDir}/*/`의 `analysis.md`와 `*-analysis.md`에서 그 프로젝트가 마지막으로 등장한 날짜를 찾아 안내하고 종료한다. 전체 이름으로 찾으며, 마지막 조각만 주어졌다면 여러 저장소가 일치하는지 먼저 확인한다.
  - 둘 이상 일치하면(다른 root 또는 같은 root의 중첩 저장소): 후보를 보여주고 `root/저장소 상대경로` 전체로 다시 지정하라고 안내하고 종료한다.
- **slug** = 확정한 전체 이름의 `/`를 `--`로 바꾼 것. 예: `vlending--team--muah-web`. 기존 dig 기록은 첫 제목의 전체 저장소 이름도 확인하고, 같은 slug 아래에 다른 저장소가 있으면 섞어 읽지 않고 충돌을 알린다.

### 2. 컨텍스트 로드

읽는 순서대로. **raw 리포트는 이 프로젝트 것 하나만** 읽는다.

- **a. 오늘 diff** — 1단계에서 고른 리포트 파일 전체.
- **b. 이미 다룬 것** — `{reportDir}/{날짜}/`의 `analysis.md`와 `*-analysis.md`에서 이 프로젝트에 해당하는 부분: 커버리지 표의 행과, 있다면 `상세 학습`의 해당 절. 없으면 "오늘 분석에서 요약만 됨"으로 기록한다.
- **c. 시간축 인덱스** — `{reportDir}/*/`의 `analysis.md`와 `*-analysis.md`에서 이 프로젝트의 **커버리지 표 행**만 모아 날짜를 앞에 붙여 정렬한다. 현재 형식은 프로젝트 열의 전체 이름으로 정확히 대조한다. raw 리포트는 읽지 않는다 — 수백 KB다.
  - **최근 90일로 제한한다.** 이 인덱스는 매일 커진다. 90일이면 200행 안쪽이고, 전체를 읽으면 첫 질문 전에 컨텍스트를 수만 토큰 쓴다.
  - 90일보다 오래된 것이 필요해지면("작년에 이거 어떻게 했지?") 그때 날짜를 좁혀 해당 `analysis.md`를 직접 읽는다.
  - 과거 표기(`muah-web`, 주제가 덧붙은 이름)는 마지막 조각으로 후보를 찾을 수 있다. 같은 이름의 다른 저장소가 없는지 확인한 경우에만 연결하며, 출처를 확정할 수 없는 행은 별도로 알린다.
- **d. 지난 dig에서 몰랐던 것** — `{reportDir}/dig/{slug}/*.md`가 있으면 각 파일의 `### 몰랐던 것` 절을 날짜순으로 모은다. 없으면 "첫 dig"으로 기록한다.
- **e. 저장소 경로** — `config/profiles.json`의 `roots[]`에서 `name`이 리포트의 root와 같은 항목을 찾아 그 `path`에 **저장소 상대경로 전체**를 붙인다. 단, 설정된 root 자체가 스캔된 Git 저장소이면 CLI는 상대경로 대신 root 디렉터리 이름을 표시하므로 그 이름을 다시 붙이지 않고 `path` 자체를 사용한다. **이 디렉터리의 파일은 대화 중 필요할 때 읽는다. 미리 읽지 않는다.**

### 3. 첫 턴 출력

아래 순서로, 각 절은 짧게.

1. **지난번에 몰랐던 것** — d가 있을 때만. 3~5개로 요약하고, 오늘 diff와 관련 있는 항목이 있으면 그 사실을 표시한다. 같은 영역을 다시 건드리고 있으면 그것이 첫 문장이다. d가 없으면 이 절을 통째로 생략한다.
2. **오늘 diff** — a를 기준으로 분석한다. b에서 이미 상세히 다룬 내용은 반복하지 않고 "오늘 분석에서 다룸"으로 한 줄만 남기고, b에 없거나 요약만 된 부분에 집중한다. diff만으로 판단이 서지 않는 지점은 e의 저장소에서 관련 파일을 읽고, **어느 파일을 읽었는지 밝힌다.**
3. **시간축** — c에서 오늘 diff와 연결되는 과거 항목이 있으면 짚는다: 같은 영역, 같은 패턴, 이전 버그의 재발, 이전에 미뤄둔 것. 없으면 생략한다.
4. **열린 질문** — 분석하다 생긴, 사용자가 답할 수 있거나 같이 파볼 만한 질문 1~3개.
5. 마지막 줄에 정확히 이 형식의 마커를 남긴다: `[dig 시작: {slug} {날짜}]`

이후는 자유 대화다. 사용자 질문에 답할 때 diff에 없는 코드가 필요하면 e에서 읽는다.

### 4. 원칙

- 기준은 **그날의 diff**다. 코드베이스는 참고 자료이고, 질문에 필요한 파일만 읽는다.
- 이 스킬은 **아무것도 쓰지 않는다.** 기록은 `/publish`가 한다.
- 텔레그램 전송은 없다. 데스크에서 끝난다.
