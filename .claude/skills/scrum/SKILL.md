# /scrum 스킬

아침 스크럼 직전에 실행한다. `config/profiles.json`의 `scrum.root`에 해당하는 저장소들에서 **마지막 작업일 하루 전체 + 오늘 오전**의 커밋을 읽어, 프로젝트별로 짧게 정리한 마크다운을 `scrum.outputDir` 아래 `{오늘}.md`로 저장한다.

독자는 **팀과 매니저**다. 학습 노트가 아니라 업무 보고다. 무엇을 배웠는지가 아니라 무엇을 했는지를 쓴다.

## 사용법

- `/scrum` — 오늘 기준으로 실행

인자는 없다. 범위는 항상 "마지막 작업일 + 오늘"이다. 마지막 작업일 오전은 그날 스크럼에도 나왔을 수 있지만, 이틀 연속 언급되는 정도라 그대로 둔다.

## 실행 절차

### 1. 설정 확인

`config/profiles.json`을 읽어 `scrum.root`와 `scrum.outputDir`를 얻는다.

- `scrum` 블록이 없으면: `config/profiles.json에 scrum 설정이 없습니다. profiles.example.json의 scrum 블록을 참고하세요.` 안내 후 종료.
- `scrum.root`가 `roots[].name`에 없으면: 있는 root 이름을 나열하고 종료.
- `scrum.outputDir`가 `/path/to/`로 시작하면 placeholder다. 실제 경로로 바꾸라고 안내하고 종료.

### 2. 리포트 최신화

프로젝트 루트에서 순서대로 실행한다.

```bash
python3 generate.py --check-missed
```

새 리포트가 생성됐으면 다시 실행한다. 생성된 리포트가 없다고 나오면 멈춘다. 최대 7회.

```bash
python3 generate.py
```

오늘 날짜 리포트를 만든다. **진행 중(WIP) 정보는 이 리포트에만 들어간다.** 오늘 활동이 없어 "작업 이력이 있는 저장소가 없습니다"가 나오면 정상이다.

### 3. 대상 날짜 확정

- **오늘** = `YYYY-MM-DD`.
- **마지막 작업일** = `reports/` 아래 날짜 디렉터리 중 오늘보다 앞선 것을 최신순으로 훑어, 첫 줄이 `# {날짜} - {root}/`로 시작하는 `.md`가 하나 이상 있는 첫 날짜. (`analysis.md`, `-analysis.md`로 끝나는 파일은 건너뛴다.)
- 마지막 작업일이 없으면: `{root} 리포트가 없습니다.` 안내 후 종료.

읽을 파일 = 마지막 작업일의 `{root}` 리포트 전부 + 오늘의 `{root}` 리포트 전부(있으면).

### 4. 커밋 추출

각 리포트의 `## 대상 날짜 커밋` 절에서 `### ` 로 시작하는 줄이 커밋 제목이다. 리포트는 `#`을 `\#`로 이스케이프하므로 `\#time`은 `#time`, `\#comment`는 `#comment`로 읽는다.

커밋 제목의 일반형:

```
VD-8082 #time 1h #comment notifyConfirm 으로 일원화
```

- **티켓** = 맨 앞 `대문자-숫자` 토큰. 없으면 없는 것으로 둔다.
- **시간** = `#time` 뒤 값. `10m`, `1h`, `1h 30m` 형태. 없으면 없는 것으로 둔다.
- **내용** = `#comment` 뒤 전체. `#comment`가 없으면 제목에서 티켓과 `#time …`을 뺀 나머지.

**제외**: 제목이 `Merge branch`, `Merge pull request`, `semantic versioning update`, `Version update`로 시작하는 커밋.

제외 후 커밋이 하나도 남지 않는 프로젝트는 문서에 절을 만들지 않는다. 배포 버전만 올린 날은 보고할 작업이 아니다.

### 5. 정리

프로젝트별로 묶는다. 프로젝트 이름은 `root/repo`에서 `repo`만 쓴다.

각 커밋을 한 줄로:

```
- {티켓} {내용 요약} ({시간})
```

- **내용 요약**: `#comment`가 한 문장이면 그대로. 문체는 보고용으로 — "~했다", "~수정", "~추가".
- 티켓이 없으면 티켓 자리를 비운다. 시간이 없으면 괄호를 생략한다.
- 같은 티켓의 짧은 항목(15분 이하)이 여럿이면 한 줄에 ` · `로 이어 붙이고 시간은 합쳐서 한 번 쓴다.

**긴 커밋**: `#comment`가 여러 작업을 담고 있으면(보통 1시간 이상, 쉼표나 `—`로
여러 건을 나열) 한 줄로 자르지 않는다. 첫 줄에 그 커밋이 무엇이었는지 한 문장으로
쓰고, 그 아래 **하위 불릿으로 개별 작업을 나열**한다.

```md
- VD-8147 Notion 콘텐츠를 빌드 타임 스냅샷에서 런타임 API + 서버 캐시로 전환 (4h)
  - 아티클·FAQ·본문 모두 배포 없이 반영
  - 굽기 스크립트와 생성 파일 삭제(pull 충돌 원인 제거)
  - /api/cache-refresh 추가
```

4시간짜리 커밋을 80자로 자르면 실제로 보고할 내용이 사라진다. 하위 불릿은 커밋
메시지에 이미 적힌 것만 옮긴다 — 없는 작업을 만들지 않는다. 하위 불릿은 최대 6개.

한 문장으로 충분한 커밋에는 하위 불릿을 달지 않는다.

**진행 중**: 오늘 리포트에 `## 현재 작업 중 변경` 절이 있고 Staged/Unstaged/Untracked 중 0이 아닌 게 있으면, 프로젝트 마지막 줄에 `- 진행 중: {파일 수} files ({상위 디렉터리 2~3개})`. 전부 0이거나 절이 없으면 이 줄을 쓰지 않는다.

**합계**: 프로젝트별 `#time` 합. `h`와 `m`을 정확히 더해 `2h 50m` 형태로.

**분량**: 프로젝트당 커밋 줄 최대 4개, 문서 전체 커밋 줄 최대 6개. 하위 불릿은
이 개수에 포함하지 않는다. 넘치면 시간이 큰 것을 남기고 나머지는
`- 외 {N}건 ({합계})` 한 줄로. 스크럼에서 1분 안에 읽을 분량이 기준이다.

### 6. 반드시 지킬 것

- **티켓 ID와 `#time` 값은 리포트에서 글자 그대로 복사한다.** 리포트에 없는 티켓·시간·커밋을 쓰지 않는다. 합계는 실제 `#time`을 더한 값만 쓴다.
- 커밋 메시지에 없는 일을 추론해서 넣지 않는다. 내용 요약은 압축이지 창작이 아니다.
- 학습 관점 표현("패턴", "설계 판단", "재발 가능성")을 쓰지 않는다. 한 일만 쓴다.

### 7. 저장

경로: `{scrum.outputDir}/{오늘}.md`. 디렉터리가 없으면 만든다. 같은 날 파일이 이미 있으면 **덮어쓴다** — 같은 날 다시 실행한 것은 재생성이다.

형식:

```md
# 스크럼 {오늘}

대상: {마지막 작업일}{, 오늘 오전 (오늘 리포트가 있을 때)}

## {repo}
- {티켓} {요약} ({시간})
- …
- 진행 중: {N} files ({dirs})

합계 {Xh Ym} · {커밋 수}건

## {다른 repo}
…
```

프로젝트가 하나면 `##` 절도 하나다.

### 8. 완료 메시지

저장 경로, 프로젝트 수, 커밋 수, 합계를 출력한다. 텔레그램 전송은 하지 않는다.
